# Testing

Prerequisites: JDK 11 or 17, Android SDK 31, Build Tools 31.0.0, and an ignored `local.properties` with the local `sdk.dir`.

On Windows, Gradle 7.6 test workers can fail when either the project or Gradle cache path contains non-ASCII characters. Place both on ASCII-only paths. `scripts/build.ps1` checks the project path and selects an ASCII-only Gradle cache; set `NOTESHADOW_GRADLE_HOME` to choose another cache path.

Run the JVM unit tests and debug build before merging:

```powershell
.\scripts\build.ps1
```

Validate release compilation and R8 separately:

```powershell
.\scripts\build.ps1 -Tasks assembleRelease
```

Without an ignored `keystore.properties`, the release APK is unsigned. Device validation should cover TXT/EPUB import, single/dual transcript switching, note `/novst`, boss-key switching, recording, both offline ASR modes, export behavior, process restart, and persistence.

Before any `adb install -r`, verify that the candidate APK certificate matches the certificate of the installed package. The v3 package (`com.noteshadow.app3`) is installed with its dedicated v3 release certificate; a Debug APK cannot update it. Never uninstall the existing package merely to bypass `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, because uninstalling removes its private notes and session data. Use the ignored signing configuration, compare SHA-256 certificate digests, and only then perform the update.

Tablet keyboard validation must include ordinary Enter input and the `Alt+Enter` mode shortcut. The target DBY-W09 keyboard has no function-key row, so F8 alone is not an acceptable interaction path.

For the live Qwen dynamic-segmentation test, cover speech with natural pauses before and after three seconds, continuous speech longer than seven seconds, low-volume speech, and stopping within the first second. Compare the formal transcript with the preserved recording; overlap may repeat text, but it must not create an unrecognized gap at a segment boundary.

Settings validation should cover all three live modes, blocking mode changes during active transcription, mode persistence after process restart, migration of the old quality-mode switch, and Qwen-only operation without Zipformer draft output. Toggle active-work screen timeout both ways while recording/transcription is already running; the window flag should update after returning from settings while the foreground service and its CPU wake lock continue unaffected. Confirm the storage summary includes active records and the recycle bin.
Storage-location validation should confirm Settings shows the unchanged default destinations for recordings, transcripts, notes, and images; category usage includes the recycle bin; public recording and export buttons open a file-browsing view near `Music/NoteShadow` and `Download/NoteShadow` without showing a “use this folder” permission action; selecting a listed file should open it with a compatible app. Every failure path must give a usable fallback without requesting persistent directory permission. Private notes and images must open the in-app course record manager, and merely viewing these controls must never move, rename, copy, or delete data.

Novel-progress validation should cover importing multiple TXT and EPUB files (including duplicate names), setting 0%, a middle decimal percentage, a character offset, and 100%, selecting the first/middle/last EPUB chapter by its opening preview, rejecting invalid values, and preserving an independent position and EPUB chapter for every document across selection changes and process restart. On upgrade, verify the prior single document is migrated exactly once without deleting its old source or losing its position. Switching the current document must stop active `/novst`, prevent old mixed-page ranges from advancing the new document, keep transcripts and manual notes unchanged, and make services/course snapshots use the newly selected document. A failed or cancelled import must not add a partial item or change the current selection.
Also confirm that novel slices automatically emitted in dual-output transcript mode advance the displayed character offset and percentage, persist across restart, and remain stable when the mixed transcript is rebuilt. Single-output mode must never add reading text or advance reading progress.

Bookshelf UI refresh validation should cover empty, loading, populated, and error states in landscape; long Chinese titles; large system fonts; current-item highlighting; and TXT/EPUB badges. Confirm every action still follows its original asynchronous path: document picker import, set current, percentage/character progress, chapter selection, and refresh. Rapidly leave or recreate the Activity during a refresh and confirm stale callbacks do not overwrite the current list. While recording and live transcription are active, enter the progress page, switch the current document, return, and verify background work continues, `/novst` uses the selected document, the legacy book mirror is current, and lifecycle recovery still opens the transcript-only safe page. The graphite theme must be scoped to the progress page until each other screen is explicitly migrated.

Management UI refresh validation should cover Settings, History, and Session Detail at tablet and narrow widths, with long Chinese titles and large system fonts. On History, portrait keeps controls above the list; landscape places a scrollable control column at about one third of the width and records to the right. Rotate with an active search, archive/trash filter, selected record IDs, and a scrolled list; confirm these restore without resetting the list on an ordinary detail-page return. Re-run project switching, search, archive filters, multi-select and all three batch exports without stale checked rows or shifted list indexes; in the recycle bin, the storage-summary row must never open as a record. On the detail page, play and stop every recording, edit the title, archive/restore, run all three exports, move and restore a record, and confirm permanent deletion still requires two confirmations. In Settings, verify transcription-mode disabling during active work, screen-timeout persistence, model key actions, fixed-prompt connection test, safe diagnostic refresh/clear, and public-file browsing. Enter and leave all three screens while recording and live transcription are active and confirm background work continues.

Main-workspace UI validation should cover single-output realtime transcription, dual-output mixed transcription, timestamp-note edit/preview, and file-transcription preview in landscape, narrow width, and large system fonts. The left navigation has realtime transcription and notes; single/dual output is selected in the shared header. Verify that single output contains only formal transcription, dual output can mix novel slices, and the legacy pure fake-typing page has no visible entry. Cold launch, lock-screen/background recovery, and the first boss-key press must show single output immediately; a second boss-key press may restore the prior view only within the same uninterrupted foreground session. Starting recording or transcription from single output must keep that view. Re-run title tap/long-press, direct sidebar navigation, `Alt+Enter`, new lesson, More-menu actions, and media-picker return; only the one-shot note media return may bypass the transcript-only safe page. Switch repeatedly between note editing and Markdown preview with large tables and images, then destroy/recreate the Activity during image decoding and confirm no stale image, crash, leaked old page, or source-text mutation. All recording/transcription work must continue while switching views or opening secondary screens.

History validation should confirm that existing session directories remain unchanged, newest records appear first, empty/disguise-only sessions stay hidden, formal transcripts and drafts open correctly, every session recording can be played and stopped, and a single-record export contains only the canonical meeting transcript. Also cover missing or damaged metadata and an unreadable recording without crashing the list or detail page.

Privacy and long-session validation should confirm that the display does not time out while recording, live transcription, or file transcription is active; that stopping the last active task restores the normal screen timeout; and that cold launch plus return from lock screen/background first shows the transcript-only “实时转写” page without reading content.

Timestamp-note validation should cover hardware and software Enter, consecutive blank lines, multiline CR/LF/CRLF paste, selection replacement, cursor insertion in the middle of a line, and persistence of text/cursor/scroll across process restart. Start recording and live transcription while staying on the note page, confirm incoming transcription never changes the manual note, then switch to both the meeting and transcript-only pages and verify all background results are present. Rapidly alternate the note and safe pages while continuing to type; an older asynchronous save must never overwrite newer text. Starting a new lesson must snapshot the previous course note, make note-only courses visible and searchable in history, and clear the active note text, selection, and scroll state for the new lesson. Older sessions without a timestamp-note file must still load normally.

Markdown-note validation should switch repeatedly between edit and preview with headings, nested ordered/unordered lists, task lists, bold/italic/strikethrough text, quotes, horizontal rules, escaped punctuation, inline code, fenced code blocks with language labels, timestamped GFM-style tables, HTTPS/HTTP links, timestamps, and malformed syntax. The saved note must remain the original Markdown source; previewing must never execute `/lm` or `/arc`, alter timestamps, or make non-web URI schemes clickable. Complete a delayed model reply while preview is visible, then return to editing and confirm the answer and cursor-safe source are retained. Page switching, process restart, and starting a new lesson must preserve the existing timestamp-note behavior.
For native table preview, verify header styling, cell borders, left/center/right alignment markers, long-cell wrapping, wide-table horizontal scrolling, and the timestamp column. Put images and links before, after, and inside table cells, rapidly toggle edit/preview while images decode, and confirm images never appear in the wrong block. Tables over 120 rows or 16 columns must show a truncation notice without freezing, while their Markdown source and export remain complete.

Image-note validation should take a photo and import JPEG, PNG, and WebP files from the course-note editing page, then confirm that each image is appended at the latest timestamped line and appears in preview without changing the Markdown source. Add at least four high-resolution photos and confirm later photos are rendered as memory-bounded thumbnails instead of remaining as italic placeholders; originals in storage and exports must remain unchanged. Completing or cancelling either picker in the same Activity instance must return directly to the note page; process recreation and unrelated background/lock-screen recovery must still use the transcript-only safe page. Rotate/background the app while a picker is open, reject a corrupt or over-25-MB file, and confirm another course cannot resolve the image path. Verify new-lesson snapshotting, archive/restore, recycle-bin restore, image space totals, and single/batch note-package ZIP exports preserve the note and its `attachments` files. A capture still in progress or abandoned temporary file must not be included in an export.

Complete-course-package validation should cover single and selected-record export on both the detail and history pages. Each record directory must contain a non-sensitive manifest plus every available formal transcript, realtime draft, timestamped Markdown note, original image, and M4A recording; the note's relative `attachments/` references must still resolve after extraction. Confirm packages containing only a recording, draft, note, or transcript remain exportable, duplicate/special-character titles produce distinct safe directories, and large recordings are streamed without excessive memory use. Disguise/reading text, book state, model context, credentials, temporary captures, linked files, and paths outside the owning session must never appear. Cancelled or failed MediaStore exports must not leave a visible partial ZIP.

Novel-note validation should enter `/novst` on a complete timestamped line, then verify hardware and software-keyboard ASCII letters consume the selected TXT/EPUB one Unicode code point at a time while spaces, punctuation, digits, Chinese text, emoji, Enter, deletion, cursor movement, and shortcuts remain literal. Enter must still add a timestamp. Exact `///` must end novel substitution; when substitution is inactive it must retain its existing `/lmcl` ending behavior. `/novst` must not start inside LM block/continuous modes, without a reading document, or at the end of the document. Reaching the end while typing must stop substitution without swallowing the triggering letter. New lesson and process recreation must start with substitution disabled, while recording and transcription continue independently.

`/arc` validation should cover default five lines, `/arc n` for fewer/more available lines and the 200-line limit, malformed numbers, empty formal transcript, insertion in the middle of a note, original ASR timestamps, and process restart. Confirm that partial results, Zipformer drafts, novel display text, and the previous course never enter the excerpt. While transcription continues, a newly confirmed line should become available to the next `/arc`; the command must not call the model or upload anything. Within `/lmlbg`…`/lmled`, `/arc` text should stay literal rather than running the command.

Model-note validation should configure a key through import, paste, or custom interface settings without displaying or logging it. On the note page, test `/lm question` and compatibility `/ds question` with hardware and software Enter; test `/lmlbg` with multiple question lines followed by `/lmled`, `/lmcl` with two sequential prompts and exact `///` termination, and `/lmnew`. Confirm all modes share successful prior model turns only, remain scoped to one course across process restart, and clear on `/lmnew` or new lesson. Also test no-key, empty and overlong prompts, offline/invalid-key failure, transcript-safe page switching, concurrent queued requests, edits while waiting, and invalidation of an in-flight reply after reset or new lesson. Requests may include the explicit question and successful prior model turns only; recordings, transcripts, unrelated notes, and reading documents must not enter the request. Check custom HTTPS URL/model ID, output token cap, optional `/models` discovery/fallback to manual ID, clear-both-keys behavior, and a `finish_reason=length` truncation notice. Never commit or bundle any API key or staged import file.

After starting recording, immediately try the first `/lm` without `/lmnew`: it must reply in the recording's new course, not stop at `REQUEST_CANCELLED GENERATION`. Repeat after stopping and starting a second recording and after a process restart. Switching courses must clear prior successful model turns, while unrelated note text and transcription remain outside the request.

Model-diagnostic validation should test `/lm` when inserted before existing note text, check that the active-interface key status—not any other provider's key—is shown in settings, and run the fixed-prompt connection test with valid key, no key, invalid key, timeout, and HTTP 400/402/422 responses. Verify request/answer stages and safe failure categories appear in the settings log and `NoteShadowLM` logcat tag, while question text, model answer, endpoint URL, credentials, transcript, and recording never appear. Clear/refresh should affect only the diagnostic log; process restart should retain bounded recent entries.

Verify `/lmnew` is shown as a manual model-context reset, not as a cancelled request. An actual `REQUEST_CANCELLED GENERATION` before `/lmnew` must remain distinguishable.

Navigation validation should confirm that the page menu can always open meeting, manual-note, and transcript-only pages directly. The title, Alt+Enter, and transcript-page shortcut may return to a work page only within the same uninterrupted foreground session; cold launch, process recreation, screen lock, background recovery, settings return, and file-preview safety switching must all show the transcript-only page with no return target. The safe page must not expose an edit shortcut into meeting content.

Project-management validation should cover old records remaining in the default project, project create/rename/switch persistence, new-session assignment, record-title special characters, search of formal transcripts and drafts without matching disguise text, archive/restore without moving files, and multi-select ZIP export containing only UTF-8 formal transcripts. Normal browsing must not carry stale checked rows into export selection, and project changes or current-record archiving must be blocked during live recording/transcription.

Recycle-bin validation should cover moving normal and archived records, preserving the original project/title/archive state on restore, refusing restore conflicts, and showing separate text/recording/total byte counts. Confirm that an active current session cannot be moved or permanently deleted, moving an inactive current session creates a fresh current-session pointer only after success, and a failed move leaves the pointer unchanged. Permanent deletion must require two confirmations, leave public exports untouched, retain a retryable marker after partial failure, and refuse traversal, linked containers, linked session directories, or linked content. Also smoke-test history and recycle-bin entry on Android 6/7 because production path checks must not depend on API-26 `java.nio.file` APIs.
