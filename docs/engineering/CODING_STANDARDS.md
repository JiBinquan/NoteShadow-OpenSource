# Coding Standards

- Follow the conventions already established in the affected module.
- Keep changes narrow; avoid unrelated formatting and refactoring.
- Prefer clear names and small units with explicit responsibilities.
- Handle failures at the boundary where useful context is available.
- Do not introduce dependencies without a concrete need and review of maintenance/security impact.
- Add comments for intent or constraints, not a narration of obvious code.
- Update relevant tests and durable documentation when behavior or workflows change.

Add language-specific rules here only after the project selects a stack.
